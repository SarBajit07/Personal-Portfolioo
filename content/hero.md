# Hero copy — candidates

Rules from Phase 0: 15 words maximum, hand-set line breaks, names the work rather than the job title. `/` marks a deliberate line break.

---

## A — the work, plainly

```
Full-stack engineer in Kathmandu. /
I build sign-language translation, /
B2B commerce, and cross-border health systems.
```

Concrete and unadorned. The three domains are unusual enough together that the sentence carries itself. Safest option.

## B — lead with Ishara

```
I'm building a real-time translator /
for Nepali Sign Language. /
Also: export platforms, health systems, field CRMs.
```

Puts the distinctive project first and lets the rest trail as an aside. Best if Ishara is live and demoable — the hero artefact then sits directly beside the claim it makes.

## C — the constraint as the hook

```
Most software in Nepal is built /
for infrastructure that doesn't exist yet. /
I build for the one that does.
```

Strongest voice, highest risk. Only works if the case studies actually back it up — offline behaviour, low bandwidth, real device constraints. If they don't, use A.

---

**Recommendation:** A, unless the answer to Q25 in `QUESTIONS.md` is that a demo capture exists — then B.

**Sub-line** (18px, `--ink-2`, one line): current role and availability. Filled from Q6 and Q8.

**Never:** "passionate", "crafting", "digital experiences", "turning ideas into reality", "let's build something amazing". A typewriter effect on any of the above. <!-- tell-audit-ok -->
